## 0. Contract (freeze into F8)

```text
Plan ≠ Reality
Plan 也不能凌驾于 Actual
```

**Precise form**:

> Plan 是对未来的意图/预期；Actual 是已经发生的场景事实。  
> 当前者的前提被后者否定时，Plan 必须失去「直接执行资格」，  
> 但不因此自动改变 Canon、State 或 Reality。

这是既有 `Plan ≠ Reality` 的自然延伸，不是新哲学。

**Repair ≠ Regenerate**（硬边界）:

| Mode | Allowed? | Meaning |
|------|----------|---------|
| **Validity Check** | ✅ | Actual vs N+1 Plan → VALID / INVALID |
| **Plan Repair** | ✅（最小） | 仅修复被否定的开场前提 / 执行资格；保留章级意图 |
| **Plan Regenerate** | ❌（默认禁止） | `Actual → Planner.replan` 洗掉整章 scenes goals |

禁止默认路径：

```text
Actual → Planner → 全部重新规划
```

## C. 最小插入点（Plan Validity Check）

### C.1 唯一需要的读口

已在内存同时具备：

- **Actual**：`prev.observedContinuity`（+ 可选 `prev.text` tail）  
- **N+1 Plan**：`scene.goal` / `scenePlan` /（Director 后）`executionPlan.scenePlan.goal`

**不需要**新 State Source。

### C.2 候选缝（按推荐序）

| # | Seam | When | Pros | Cons |
|---|------|------|------|------|
| **1 ★** | Scene pipeline：`ensureObservedContinuity(N)` 之后 → **N+1 `plan` hook / Director 之前** | orchestrator / studio-orchestrator 场间 | Check 早于 HARD Goal 锁定；Repair 可降权再进 Director | 需显式场间调用 |
| **2** | Director `buildSceneExecutionPlan` 入口 | `prevScene` + `scene.goal` 已在 | 能改 situation.before 而不碰 Canon | 易膨胀成「半个 Engine」——须锁死只读 Validity + 局部 Repair |
| **3** | `compileScenePrompt`：`collectPreviousObservedContinuity` 之后 | L1 编译时 | 纯函数友好；已有 `planText` 参数 | Goal 可能已在上游 Director 锁定；偏晚 |
| **4** | `compileSlimBeatUserPrompt`（已有 `hasUnresolvedOc` 措辞门） | L4 | 最近 Writer；改动面小 | **太晚**：Goal 仍以 CURRENT INTENT 注入；仅措辞不足以修 F8.1 |

**推荐主缝：#1**（pipeline 场间）  
**推荐辅缝：#4 仅作 INVALID 时的执行资格降级**（Goal 标签 demote），不是唯一修复点。

现有微弱先例（**不够** F8.1）：`beat-slimmer.js` 在 `hasUnresolvedOc` 时仅改 Goal 旁注「不得把 unresolved 改写成已结算」——**仍完整注入医院 Goal 为 CURRENT INTENT**。Ch2 S2→S3 即在此配置下失败。

### C.3 Ownership 裁决

| Layer | Role for F8 |
|-------|-------------|
| **Pure function / diagnostic** | ★ **Validity Check 本体**：`evaluatePlanValidity(actualOc|text, nPlus1Plan) → { status, conflicts[] }` |
| **Scene pipeline** | ★ **调用点**：场间 invoke；挂 `planValidity` 结果到 scene（session / prompt-facing；≠ Canon） |
| **Director** | 可选 **Repair consumer**（只修 opening premise / situation.before）；禁止变成 Consequence Engine |
| **Prompt compiler / beat-slimmer** | **执行资格降级**：INVALID → Goal 失去 HARD「直接执行」措辞 |
| **Planner `replan`** | ❌ 默认不走；与 Repair 分离 |

**不属于**：新 Beat Engine · Consequence Engine · 第二 State Source · F6.2 binder 重写 · F7.1 Expected 语义重开。

## D. Minimal Repair Architecture（设计 only）

```text
Scene N Actual (text → OC)
        ↓
evaluatePlanValidity(OC, N+1.goal|scenePlan)     ← pure
        ↓
   Plan Validity
 ┌───────────┬────────────────────────────┐
 │ VALID     │ INVALID                    │
 │ 原 Plan   │ 标记冲突（premiseDenied）   │
 │ 继续      │ ↓                          │
 │           │ Plan Repair（局部）         │
 └───────────┴────────────────────────────┘
                    ↓
         repaired intent（仅 N+1 开场资格）
                    ↓
              Director / Writer
```

### D.1 Validity（必须先做）

**INVALID 仅当**（对齐 F8.1 Case 3，避免 Case 1 误杀）：

- Actual 已否定 N+1 Goal 的 **开场前提**（地点/未结算选择/关键对象状态/行动前提已不存在等）
- 不是「Actual ≠ Plan 文风差异」
- 不是「Goal 未从 Actual 自动重写」本身（那是 Bypass，不是 Failure）

输入优先：`observedContinuity.unresolved`（如 `open_choice_*`）+ Goal 文本前提启发式；**输出是诊断，不是 Reality。**

### D.2 Repair（允许的最小动作）

按强度递增；实现门未开前只冻结菜单：

1. **Demote execution privilege**（最小、优先）  
   - Goal：`CURRENT INTENT` → `DEFERRED / PREMISE_INVALID`  
   - Writer 必须先 bridge/settle Actual，或显式偏离并承接  
   - **不删**作者 Goal（保留预规划价值）

2. **Local premise repair**  
   - 仅改 N+1 `situation.opening` / 首拍 Before / 衔接指令  
   - **不**重写整场 Goal，**不**级联 S+2…Sk

3. **Flag for author / Studio**  
   - 表面化冲突；人可确认「保留未来医院 beat」

### D.3 Forbidden Repair

- `planner.replan` 因单场 Actual 重洗整章  
- 把 OC 升格 Canon / SR / StoryState  
- 新建 Consequence / Pressure / Situation Engine v2  
- 修改 F6.2 binder 语义或 F7.1 Expected 合同  
- 让 Beat After 变成 Actual

### D.4 对 F8.1 失败的设计映射

```text
Ch2 S2 Actual: open_choice + 三十秒（公司）
Ch2 S3 Plan:   已在病床 4:00
→ Validity: INVALID（开场前提被否定）
→ Repair: Demote S3 Goal 执行资格 + 要求 bridge/settle
→ 禁止: 直接 CURRENT INTENT「写医院醒来」
→ 仍可保留: 「医院见证刷新」作为远期意图（作者 Plan 价值）
```

## E. Freeze proof（严格边界）

| Constraint | How F8.2 design respects it |
|------------|-----------------------------|
| 不写 Canon | Validity/Repair = session/prompt 投影；`writesCanon: false` |
| 不写 Reality | 不宣布新世界事实；只裁定 Plan 执行资格 |
| 不写 SR | 不碰 Minimal SR persistence |
| 不改 F6.2 | OC 仍为 observation projection；Check **读** OC，不重定义 binder |
| 不改 F7.1 | Expected 标签保留；Demote 的是 **Scene Goal 执行资格**，不是 Beat 升格 |
| 不增加 Beat Engine | 不新增六拍/库拍系统 |
| 不增加 Consequence Engine | 无 Consequence Object 持久化；尚未证明其必要（F8.1） |
| 不制造第二 State Source | 无新 durable world state；最多 `planValidity` 诊断字段挂 scene |

**尚未证明必须建立 Consequence Object** — F8.2 维持该结论。若纯 `planValidity` + demote/local repair 能挡住 Case 3，则 **不需要** Engine。
