## 2. `evaluatePlanValidity`

```text
packages/inkos-prompt/src/plan-validity.js
```

Pure diagnostic. Output shape:

```text
{
  role: 'plan_validity_diagnostic',
  status: 'VALID' | 'INVALID',
  conflicts: [...],
  premiseDenied: boolean,
  evidence: [...],
  executionPrivilege: 'direct' | 'demoted',
  strategicGoalPreserved: true,
  writesCanon: false,
  writesReality: false,
  writesSR: false
}
```

**INVALID only** (high precision):

- **A** Location: Plan establishes hospital-bed opening; Actual location ≠ hospital; no bridge language  
- **B** Choice assumed settled: unresolved open_choice **and** Plan assumes arrival/wake **without** bridge  
- **C** Object state: literal opposite (e.g. key surrendered vs still using key)

**Explicitly NOT INVALID**: unresolved alone · emotion · new suspense · Actual≠Plan prose · FP-1…FP-4 cases.

## 4. Ch2 S2→S3 replay

**Old behavior (F8.1)**:

```text
Actual (公司 · 三十秒未结算)
  → S3 Goal HARD〔CURRENT INTENT〕医院病床醒来
  → Writer 直接病床 · 因果断裂
```

**New behavior (F8.3)**:

```text
Actual
  → planValidity.status = INVALID
  → executionPrivilege = demoted
  → Strategic Goal 文本保留（医院叙事目标仍在）
  → L1/L3/L4: 〔STRATEGIC · 保留〕+ Plan Validity block
  → 禁止把「已在病床 / 选择已结算」写成开场既成事实
  → 必须先承接 / 结算 / 桥接 Actual
```

Artifact: `golden/story-architecture/validation-f8.3/s2_to_s3_l4_after.md`  
Validity JSON: `golden/story-architecture/validation-f8.3/s2_to_s3_validity.json`

**Note**: 本轮验证的是 **Prompt 执行资格闸门**（阻断 HARD 直写医院开场）。未调用生产 LLM 重生正文；成功标准按 F8.3 授权 = demotion 生效且 FP 不误杀。
